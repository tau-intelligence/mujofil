What it is

A simulation pipeline, not a new physics engine.

The honest version, up front — because positioning matters more than hype.

MuJoFil is two pieces working as one: MuJoCo Warp for high-throughput GPU physics, and an efficient, GPU-parallel rasterization renderer (forked from Google Filament) for photoreal frames. We wire them together so you get the best of both — fast parallel dynamics and fast, parallel, physically-based visuals — delivered to PyTorch with no GPU→CPU→GPU bounce for the pixels.

We don't reimplement dynamics. The simulation is MuJoCo Warp (DeepMind + NVIDIA's GPU MuJoCo). Our work is the renderer and the zero-copy GPU→PyTorch pipeline that turns GPU-resident world states into training-ready observations — something neither MuJoCo nor MuJoCo Warp's built-in raycaster does (it's flat-shaded and can't load real environments).

τ

The middle of the spectrum. Not the highest fidelity (we're rasterization — PBR, IBL, SSAO, reflections — not path-traced like Omniverse), and not the fastest (a flat raycaster trades all shading for throughput). MuJoFil targets the practical middle: photoreal-enough RGB that runs on a mid-range GPU.

How it works

From GPU physics to a torch.cuda observation.

One step of the loop, end to end.

01 · Physics

MuJoCo Warp steps N worlds

Thousands of parallel MuJoCo worlds advance entirely on the GPU as CUDA kernels.

→
02 · Render

Filament fork, one instanced pass

A forked Filament GL backend draws all worlds in a single gl_Layer pass — full PBR, IBL, shadows, reflections.

→
03 · Deliver

Zero-copy to PyTorch

Filament renders into GPU memory CUDA imports directly — frames arrive as torch.cuda tensors, no CPU round-trip.

⚡

Parallel rasterization

A forked Filament GL backend renders many worlds in one instanced draw with per-world GPU transforms — parallel by construction, not a per-world Python loop.

◳

Zero-copy observations

Pixels are exported to CUDA via GL/Vulkan external memory and handed to PyTorch through DLPack — no GPU→CPU→GPU transfer that scales with resolution.

✦

Real materials & light

Metalness/roughness PBR, image-based lighting, soft shadows, SSAO, bloom, screen-space reflections and filmic tone mapping — the appearance cues flat renderers lack.

Benchmarks

Honest numbers, freshly measured.

RTX 4060 Laptop (8 GiB), one primitives scene, full loop = GPU physics + one batched render of N worlds → torch.cuda. Subprocess-isolated, best-of-2.

Throughput — env-steps / second (128 px)

ModeN=16N=64N=256N=1024
Physics only (no vision)3,86519,11969,523307,679
MuJoCo Warp — depth raycaster6162,3668,80226,481
MuJoCo Warp — flat RGB raycaster6122,3578,45124,372
MuJoFil — photoreal RGB (default)2,1994,7567,6028,016
MuJoFil — photoreal RGB (layered)1,6926,25710,92513,933

Read it honestly. At the batch sizes most people train at (16–256), MuJoFil's photoreal RGB is as fast as — or faster than — MuJoCo Warp's own depth raycaster, while delivering full PBR. MuJoCo Warp's raycaster is a fully parallel megakernel, so it scales past us at very large N (N=1024): it wins raw throughput by trading away all visual fidelity. We're a rasterizer; we plateau. Different categories, stated plainly.

Latency — milliseconds per batched frame (128 px)

ModeN=16N=64N=256N=1024
Physics only4.13.43.73.3
MuJoCo Warp — depth26.027.129.138.7
MuJoFil — RGB (default)7.313.533.7127.7
MuJoFil — RGB (layered)9.510.223.473.5

We publish latency next to throughput on purpose. Throughput rising with N just means fixed per-batch overhead amortizes — per-frame time still climbs. The layered path's vectorized tone-map keeps that climb in check (it's ~3× faster at N=1024 than the per-world version it replaced).

i

On "300,000 steps/s". That's physics with nothing attached — a state-based RL ceiling. The moment you render pixels and run a policy network, the renderer and the encoder become the bottleneck, and practical vision-RL lives at ~1k–15k env-steps/s. MuJoFil's job is to make the render fast enough to stay off the critical path — not to pretend vision training runs at physics speed.

Get started

One install, one import.

Your code imports only mujofil_warp — MuJoCo Warp and the renderer are driven for you.

# one self-contained wheel — NVIDIA GPU + driver is all you need
$ pip install mujofil-warp
import mujofil_warp

# GPU physics (MuJoCo Warp) + photoreal rendering, one object
scene = mujofil_warp.ParallelScene(
    "scene.xml", num_worlds=32,
    width=256, height=256, preset="high")

for _ in range(100):
    scene.step()                  # GPU physics
    obs = scene.render(camera=0)  # (32,256,256,4) torch.cuda

What you get out of the box.

Photoreal observations as zero-copy torch.cuda tensors, ready for a CNN / ViT / VLA policy. Quality presets (high, fast, train, …) trade fidelity for throughput with one keyword. Any environment via the optional [usd] tooling that converts a GLB/USD scene into a visual mesh plus a MuJoCo collision body.

The wheel is self-contained — Filament and the CUDA runtime are baked in. The only runtime requirement is an NVIDIA GPU + driver. Linux x86-64, Python 3.10–3.13.
